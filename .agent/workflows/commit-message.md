---
description: Custom commit message style for this project
---

When the USER asks you to write a commit message, or when you are generating a commit message on their behalf, you MUST follow these rules:

1. **Write it from the user's perspective** (make it sound like them, keep it casual and natural).
2. **Keep it extremely brief and simple**. Do not include too much content, explanations, or long lists.
3. **Focus only on what files were changed**. Just mention the key files that were modified.

**Example Good Commit Messages:**
- "updated main.py and settings.json"
- "fixed cors in api/main.py and ignored some md files"
- "removed emojis from FEATURES.md and related docs"

**Example Bad Commit Messages:**
- "Fix CORS policy and Next.js frontend URLs for Vercel/Render support"
- "chore: update .gitignore to include FEATURES.md and errorlog.md"
